# Domain docs

This repository uses a single domain context for the library and documentation site. When present, read the root `CONTEXT.md` and relevant ADRs in `docs/adr/` before working in an area. Proceed if those files do not yet exist; domain-modeling creates them when terminology or decisions need recording.

Use the glossary's terms in issues, tests, and design work. Flag any conflict with an existing ADR rather than silently overriding it.
